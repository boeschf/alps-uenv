# 26.11 maintainer notes and user-only build handoff

[README.md](README.md) is the user guide. This recipe has **not** been configured or built with Stackinator during the 26.11 work. Development used downloaded binaries and disposable real-bubblewrap runtime fixtures, not an installed 26.11 image. No real user profiles were changed.

## Recipe and package constraints

- Versions: OpenCode **2.3.0**, OMP **18.22.0**, Prime Agent **0.10.3**, Paseo **0.16.1**; internal launcher/model-config/local-skills packages **2026.11.20**. Official ARM64/x86-64 assets and licenses are pinned in their packages; checksums belong there, not in a second documentation table.
- Spack is pinned to `v1.2.2`; `spack-packages` to `7318c6ac1a452a5e9f433d6de81841a036114e8f`. Recipe store is `/user-tools`; default environment/view is `agents`, with GCC 14, `unify: true`, `link: roots`, and `add_compilers: false`.
- Keep `cleanup: runtime`. Keep `squashfs`, `crun`, `catatonit`, and `fuse-overlayfs` explicit roots: cleanup otherwise can remove Stackinator's implicit packaging tools or runtime tools addressed by absolute package paths. Native harnesses are launcher dependencies, not bare view roots; bare Paseo is exposed for remote CLI control, but local daemons must use `paseo-bwrap`.
- `cscs-agent-launchers` owns common argument parsing, profile/bind policy, SSH-agent checks, mutable-tool bootstrap, managed model configuration, skill links, and storage supervision. Do not fork a second launcher convention. `content_hash()` includes runtime helpers/templates/defaults; unresolved substitution tokens are errors.
- OpenCode uses checksummed official native npm archives, not a Bun/Node source build. Its foreground-owned private server remains inside the writer lease. The managed read-only `service.json` disables detached service startup, and inherited `OPENCODE_CONFIG_DIR` cannot redirect the profile. Review custom SDK/OpenTUI plugins across the 2.2/2.3 changes.
- OMP uses native official binaries. Preserve install-time ED3 scrollback mutation and runtime interactive ED3 filtering; the latter can be disabled with `OMP_BWRAP_FILTER_ED3=0`. The supervisor now forwards `SIGWINCH` to the new child process group with separate pending resize/termination state and handles child-exit races. Real PTY regression and actual ARM64 TUI reflow were observed; tmux remains untested.
- Prime must retain its entire standalone runtime archive next to its executable. The launcher supplies native model/settings paths, persistent sessions/kernel venv, and local overlays for `session-leases`/`daemon-workers`. The guard's lifetime owns the daemon lease; socket identity includes node boot, Slurm allocation, profile, project, executable, and isolation policy. A management query must not start a daemon. Prime appends `/v1/messages`: its provider base must be the production **origin**, unlike the `/v1` base used by OpenCode/OMP.
- Paseo uses Node **22.22.2**, staged npm **10.9.4**, and committed production `package.json`/lock inputs. Spack Node deliberately omits npm: use the staged npm CLI through the absolute Spack Node, never host npm. Keep separate npm user/global config files. `npm ci --ignore-scripts --omit=dev --include=optional` selects published native optional packages without lifecycle compilation. Both architecture layouts must remain covered.
- The **Paseo package** owns `patch_omp_approval.py`, applied to staged dependencies during installation and included in its content hash. It fingerprints the pinned upstream mapper, accepts only known OMP approval layouts, exposes only invocation-scoped approval, and leaves generic questions as forms. Reapplication is a no-op; unknown source fingerprints fail rather than silently skipping the correction. The semantic Node regression and real CLI-mediated allow/deny paths passed; browser/UI approval remains unverified.
- `crun`/`catatonit`/`fuse-overlayfs` support opt-in host podman under a user/mount namespace. FUSE overlay avoids unavailable mount-privacy operations; setuid fusermount is not a solution under nosuid/no-new-privileges restrictions. Layers/runtime are local RAM-backed data, not checkpoint payload. Container execution is not yet validated for 26.11.

## Invariants to preserve

**Storage and authority.** Root read-only; normal homes and `/tmp` hidden; project/profile/explicit binds writable. SSH-agent forwarding is opt-in. A distributed single-writer profile lease spans nodes, with serialized acquisition/recovery. Lease recovery quarantines only after the owner is known dead. SQLite/WAL and machine-local locks run on validated local storage; durable immutable checkpoints and bulk histories remain persistent. Do not open SQLite directly on live NFS data. Restore validates inventory/database health and tries older generations, including when `current` is absent/empty. A healthy but empty newest checkpoint still requires human history selection, not a guessed home-to-project migration.

**First-launch migration.** Discover older stored home roots or the same project-local instance, independently of installed images; include skipped releases and known unversioned `*-spack` home profiles, never newer releases. Empty/cache-only old profiles are not candidates. Interactive source selection and approval are distinct; headless copying needs `--migrate-profile` and, when ambiguous, `--migrate-from`. No source means fresh startup, not an error, unless the user explicitly requested a missing selector. Copy portable config/auth/history/checkpoints/bulk data under source and destination writer/maintenance leases; legacy writers without this protocol must be stopped manually. Never merge initialized destinations or mutate original persistent files. Do not create a redundant source backup. Private staging, no-replace publication, and durable external journals make interrupted copies fail closed, including when target roots are accessed explicitly. Paseo's native owner and dependencies are copied together; safe linked worktrees receive independent metadata rather than keeping rollback-profile Git administration live. Managed defaults need hash ownership before regeneration. Prime kernel environments and cache/runtime state regenerate.

Publication uses exclusive directory/symlink creation and hardlinks of **private copied staging files**, never hardlinks to original profiles. Existing entries cannot be replaced or merged; the durable journal guards partial publication, and empty destination roots become mode `0700` before credentials are published. Do not replace this with plain rename or require `RENAME_NOREPLACE`: [Linux NFS rejects nonzero rename flags](https://github.com/torvalds/linux/blob/v6.4/fs/nfs/dir.c#L2660), and the latter also failed with `EINVAL` on the actual CSCS Lustre smoke filesystem.

Rebase proven native owning metadata only: OpenCode v1/v2 session/project/worktree tables, project sandbox lists, versioned location events and queued moves; OMP/Prime session headers; Prime RLM topology/ledger paths and directory-derived ledger hashes; Paseo handles/registries/worktree administration. Never globally replace paths inside historical messages, prompts, tool inputs, provider settings, or unknown auxiliary ledgers.

**Mutable tools.** uv's first lock can hang on NFS before its lock timeout: both uv/Python installation and uv cache belong under local storage. Validate owned non-symlink local overrides for `CSCS_AGENT_LOCAL_STORAGE_DIR`, `CSCS_AGENT_TOOLS_DIR`, and `CSCS_AGENT_TOOLS_CACHE_DIR` before invoking uv; extra binds cannot mask these roots. Node changes re-bootstrap tools, not copy runtime locks. Model/storage helpers explicitly use managed Python 3.13 without shadowing project Python. A temporary Prime smoke fixture needed CPU affinity limited to two cores after a Rayon thread `EAGAIN`; no global thread cap was added.

**Model ownership.** Production metadata GETs only: `https://api.inference.cscs.ch/v1/models`, CSCS docs, optional public Hugging Face metadata. No experimental credentials/providers/routes/fallback, price endpoint, cost fields, or price-based selection. Defaults are GLM-5.3-Flash, Qwen3.8-27B-FP8 for smol, GLM-5.3 for slow. Thinking Apertus is excluded; normal Apertus is manual-only and must not regain default/helper/title/fallback roles. Current GLM contexts are 1,048,576, others 262,144; output budget is capped at half context. Refresh is launch-driven, production-credential-aware, 24-hour and hash-owned; user-edited files remain user-owned. Failed generation preserves complete existing files. OpenCode JSONC merging and OMP `models.yaml` precedence must remain respected. Personal providers/auth are not removed.

**Skills.** Package only local `manage-cscs-skills`, `refresh-cscs-models`, and `cscs-agent-sandbox`. Read current upstream catalogues at user request; no vendored upstream skills or startup network update. Install/update requires a selection and explicit approval after paths, exact commands, and digests are shown. Headless question unavailable/cancelled means a final plain-text question and **stop**. Modern managed Python is required for safe extraction; validate archive hash and safe staged extraction, record `.digest`, protect conflicts, and preview backups of local edits.

Canonical durable storage is `${XDG_DATA_HOME:-$HOME/.local/share}/cscs/skills`, or absolute `CSCS_AGENT_SKILLS_DIR` ending in `/cscs/skills`. Preserve the override through Paseo/nested helpers. Bind only that subtree writable at itself and at sandbox `$XDG_DATA_HOME/cscs/skills`; OMP's other XDG data remains local. Discovery: OpenCode `$XDG_CONFIG_HOME/opencode/skills`, OMP `$HOME/.omp/agent/skills`, Prime `$PRIME_AGENT_CODING_AGENT_DIR/skills`. Per-link ownership markers repair managed links but preserve user-owned directories/dangling symlinks. Host architecture-qualified XDG affects default skills too; explicit shared root is opt-in. Paseo workspace HOME/XDG may differ from native helper HOME/XDG: canonical env is authoritative, with native initialization synchronizing discovery links.

**Paseo.** Password required even on loopback; password grants owner authority. Public relay, voice, and dictation stay disabled. There is no scheduler, automatic discovery, Hub enrollment, or live host migration. Native OpenCode/OMP use guarded wrappers (Prime has no adapter); OpenCode version probes bypass mutable initialization. Bind its native plugin read-only, retain explicit worktree access, and route existing history only via the selected owner. Isolated/home/project history selection is fixed per Paseo profile; OMP isolated session identity must use persistent paths, not transient PIDs. Checkpoint only config/keypair/server identity; never restore PID locks, local credentials, logs, generated helper/plugin/cache state. Native history retains native leases/checkpoints. UI serving/API reachability is not browser visual or approval evidence.

**Outside-sandbox consent.** The local sandbox skill must require explicit permission before any Slurm execution outside the agent namespace, including probes. Present target/allocation/account/resources, environment allowlist, CWD, paths/access, and exact command. `--uenv-passthrough=ignore` only ignores loaded uenv state; it does not itself escape a namespace. An outside Slurm task has normal host filesystem permissions. Never reinterpret a prohibited build as permission to submit one.

## USER ONLY: configure and build outside the agent sandbox

Run these commands yourself in a **fresh compute allocation obtained outside this agent sandbox**, separately on each target architecture. Do not run them through an agent shell or nested bubblewrap. Choose account, partition/resources and wall time according to site policy; no allocation or Slurm command was submitted during this work.

Build-tool paths are user-selected; the commands require explicit Stackinator, cluster-config, and optional mirror locations rather than assuming a particular installation. Start from an outside-sandbox shell on the architecture-compatible compute node/allocation:

```bash
# USER: execute on the allocated compute node, outside any agent sandbox.
export RECIPE=/capstor/scratch/cscs/boeschf/alps-uenv/recipes/cscs-agents/26.11
: "${STACKINATOR_ROOT:?Set STACKINATOR_ROOT to your Stackinator checkout}"
: "${CLUSTER_CONFIG:?Set CLUSTER_CONFIG to the matching cluster configuration directory}"
export BUILD="/dev/shm/$USER/cscs-agents-26.11-$(uname -m)"
"$STACKINATOR_ROOT/bin/stack-config" \
  -r "$RECIPE" -s "$CLUSTER_CONFIG" -b "$BUILD"
cd "$BUILD"
env --ignore-environment \
  PATH="/usr/bin:/bin:$BUILD/spack/bin" HOME="$HOME" \
  make store.squashfs NJOBS=32
```

Use a fresh build path; it must not be under `/tmp`, `$HOME`, or `/`. `/dev/shm` consumes allocation RAM; choose resources accordingly. If your Stackinator install exposes `stack-config` elsewhere, set `STACKINATOR_ROOT`/the executable path to that actual installation rather than assuming the example layout. For a configured cache, add `--mirror="$MIRROR_CONFIG"` to `stack-config` only after setting `MIRROR_CONFIG` to a real YAML file. Output is `$BUILD/store.squashfs`; copy/register it according to site practice before volatile allocation storage disappears. Do not claim the registered `cscs-agents/26.11` label exists until it does.

Build diagnostics: sandbox `/tmp/...` stage logs live under `$BUILD/tmp/...` on the host. `stack-debug.sh` accesses the sandbox store; `/user-tools` is not the host build directory. Package install mutations must be idempotent across build-cache reinstall. Preserve pristine inputs or make reapplication a no-op. A previous Bash patch-download outage was addressed by verifying upstream patch hashes and populating the configured source cache, not by weakening checksums; do not assume that historical outage persists.

## Feedback for CSCS agent documentation

The live docs/index are authoritative for upstream skill contents; keep release-specific wrapper behavior here. Useful upstream clarifications:

- Show **OMP** discovery as `$HOME/.omp/agent/skills` and **Prime** as `$PRIME_AGENT_CODING_AGENT_DIR/skills`, not a guessed generic Pi/Prime home. Distinguish application discovery links from durable canonical installation.
- Explain architecture-qualified host XDG roots and the explicit shared `CSCS_AGENT_SKILLS_DIR` option. In Paseo, workspace HOME may be the daemon's, so HOME-based installation commands can target the wrong native profile.
- Make selection/paths/digests/commands and explicit consent mandatory for bootstrap and updates; document plain-text question-and-stop for unavailable/cancelled headless question tools. Do not interpret a model's continued execution as consent.
- Document outside-sandbox Slurm authority separately from uenv passthrough. Never suggest scheduler execution as an implicit workaround for a forbidden build.
- Separate checksums/unit tests/ARM64 native fixtures/HTTP reachability from built-image, x86 runtime, tmux, actual browser approvals, containers, and scheduler validation. Publish only the validation actually performed.
